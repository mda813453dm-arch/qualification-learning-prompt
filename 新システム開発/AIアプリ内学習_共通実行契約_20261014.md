# AIアプリ内資格学習：共通実行契約（2026-10-14）
本書は新システム開発ブランチ用。main と master_prompt.txt は変更しない。ユーザーは ChatGPT または Claude の標準AIアプリの会話画面で学習する。外部HTML学習画面・PC・追加有料APIを前提にしない。

## 画面の必須動作
1. 資格・学習状況・免除の確認→学習計画の提示→「解説／確認問題／実践問題」の開始選択。
2. 解説後は確認問題か実践問題へ。確認問題で正解するたび「確認問題を継続／実践問題へ」をユーザーに尋ねる。
3. 実践問題は公式過去問を優先し、問題本文・全選択肢・必要な公式図・同年度同区分の正答資料を直接照合して出題。取得不能なら有限探索後にPDF添付依頼または明示したAI作成実践問題への切替を案内する。
4. 同一項目で有効な実践3問連続不正解→確認問題。別項目の誤答を混算しない。
5. ユーザーは随時分野・項目・モードを変更可能。回答待ち問題と採点スナップショットを取り違えない。
6. 学習順は根拠のある頻出分野順→公式資格概要の分野順→両方不明なら記録済みランダム順。免除適用確定の範囲は必修から除く。
7. 正誤・理解不足から項目別復習単位を登録し、1/3/7/14/30日を基本に再出題。定着で間隔を延ばし、習得後に復習対象から卒業。再誤答で復帰。期限割込み後は元の工程へ戻る。

## 責務と制約
- 決定的エンジン：学習計画と順序、状態遷移、項目別誤答数、復習キュー、問題セットと採点証拠の整合、保存形式を扱う。
- AI：自然言語の入力理解、説明、確認問題生成、弱点分析、学習支援を担当。プログラム未実行なのに実行済みと報告しない。
- ChatGPT/Claudeへのプログラム接続は未実証。GitHub上のJavaScriptはAIアプリ会話で自動実行されない。接続未成立時はプロンプト駆動の会話学習として動作し、外部永続保存・厳密な自動状態管理を保証しない。アプリ別に実機テストを実施して区別する。
- 正本：[Notion 学習モード・状態遷移仕様](https://app.notion.com/p/3f99454467c0816a810bfd6701854172)。既存マスタープロンプトとの矛盾を勝手に上書きしない。

## 受入テスト
初期質問・計画提示・3モード開始、解説後分岐、確認正解後の意思確認、公式PDF取得・正答照合、取得失敗時の代替、3連続誤答の項目境界、分野変更、復習期限・卒業・再登録、アプリ再開時の状態をそれぞれ確認する。GitHubの単体テストPASSとAIアプリ実機PASSを別々に報告する。

## 初心者にも分かりやすい質問解説
- ユーザーの自由な質問には中学生・初心者にも分かるやさしい日本語で、正確かつ丁寧に回答する。専門用語はその場で説明する。
- 必要に応じて「結論→身近な具体例→試験のポイント→短い覚え方」で説明し、簡単な質問には簡潔に答える。例えや語呂が正確性を損なう場合は使わない。
- 学習中の自由質問を選択肢の回答として誤採点しない。質問後に元の問題・モードへ戻れるように状態を保持する。
- テスト：初心者の自由質問への平易な説明、覚え方、出題中の質問割込みと復帰を検証する。

## 適宜のモチベーション支援
- AIは問題・解説・復習の合間に、根拠のある学習行動や進歩に即した短い励ましを自然に挿入する。既定は控えめで毎問必須ではない。正解時は定着を、不正解時は見直すポイントと再挑戦を支援する。
- 「必ず合格」「完璧」など根拠のない断言や過剰な称賛を禁止。ユーザーの「声かけ不要／少なめ／多め」を尊重する。
- 励ましは公式問題本文・選択肢・図表・正答の外に置き、回答待ちや採点・次問遷移を妨げない。テストでは正誤・復習・抑制指示・次問進行を検証する。

### 声かけの自然さ・絵文字
- AIは状況に応じてその都度言葉を考え、同じ定型文を毎回繰り返さない。声かけを省略する回も設ける。
- ✨💡📘👏などの絵文字は必要に応じて少数使用。毎回必須ではなく、不正解時の軽薄な表現や過剰な絵文字を避ける。ユーザーの絵文字不要・頻度・口調指定を優先する。
- コメントは公式問題や採点根拠の外に置き、未確認の進歩を断言しない。連続出題時の反復抑制を受入テストに加える。

## 初回導入の厳格な順序（2026-10-14 実機指摘反映）
資格名入力後の画面は必ず次の順序で進める。段階を飛ばさない。
1. **試験概要表示**：試験の対象、出題分野、出題形式・試験時間・合格基準など公式資料で確認できた事項を、初心者にも分かる言葉で表示する。未確認の項目は未確認と明記する。
2. **免除利用の確認**：公式試験概要で免除制度が存在すると確認できた資格に限り、対象・適用状況を質問する。制度のない資格では質問しない。
3. **学習状況の聴取**：未着手／基礎／応用／過去問等の段階を一度確認する。必要事項以外を繰り返し聞かない。
4. **個人別学習計画の作成・表示**：頻出分野優先（根拠必須）、公式概要順、固定ランダム順の順に判断。免除範囲を除外し、開始分野と理由、学習方法を示す。
5. **開始確認**：「この学習計画で開始しますか？」と明確に尋ね、ユーザーの承認を待つ。承認前は出題・解説を開始しない。
6. **開始後の学習モード選択**：解説／確認問題／実践問題の希望を確認して開始する。開始承認とモード選択は必要に応じて一画面にまとめてもよいが、承認前に学習を始めない。
### 遷移ゲート
資格確定→OVERVIEW_SHOWN→EXEMPTION_RESOLVED_OR_NOT_APPLICABLE→STAGE_RECORDED→PLAN_SHOWN→START_APPROVED→MODE_SELECTED→STUDY。必要な前状態を満たさない遷移は拒否する。
### 回帰テスト
- 宅建：資格名入力後は試験概要を先に表示し、免除確認をその後に行う。
- 免除制度のない資格：免除確認を省略して学習状況へ進む。
- 学習計画表示後：開始承認まで出題しない。

## 試験概要取得の必須ゲートと代替探索（2026-10-14）
### 取得手順
1. 資格名確定後、まず試験実施機関等の公式サイトから試験概要を取得する。試験対象、出題分野、出題形式、試験時間、免除制度などを確認し、出典と確認状況を記録する。
2. 公式サイトの取得に失敗・一部欠落した場合、同じ公式機関の別ページ・公式PDF・公式案内・別取得経路を試す。即座に「非対応」と判定しない。
3. それでも不十分なら予備校・資格学校・信頼できる試験情報サイト等を複数探索し、試験概要の必要事項を可能な限り収集する。非公式情報は出典を明示し、公式確認済みと表示しない。食い違う事項は未確認とする。
4. 少なくとも当該資格を特定でき、試験対象・出題分野が十分に把握できて学習計画を組める場合だけ概要表示へ進む。確認できない場合は「この資格は、試験概要を十分に確認できなかったため、現在対応できません。」と明示して学習開始を終了する。根拠のない分野・問題を作らない。
5. 公式の免除制度を確認できた場合に限り免除利用を質問する。非公式情報だけで免除の有無や範囲を断定せず、必要なら追加の公式確認を行う。
6. 試験概要の確認と公式過去問・正答PDFの取得は独立したゲートとする。概要を非公式資料で補えても公式過去問の取得・照合が成功したことにはならない。公式問題を確認できなければ、規定のPDF添付・明示的AI作成切替を案内する。
### 導入順序
資格名入力 → 公式優先・代替探索による概要取得 → （十分な概要取得失敗なら非対応終了） → 試験概要表示 → 免除利用確認（公式制度ありのみ） → 学習状況聴取 → 学習計画表示 → 開始承認 → 学習モード選択 → 学習。
### 回帰テスト
- 公式取得成功時は公式概要を表示し次へ進む。
- 公式取得失敗でも予備校等から十分な概要を取得できれば、非公式の出典を明示して次へ進む。
- 公式・代替サイトの双方で概要が不足する場合は非対応表示して終了し、学習計画や出題へ進まない。
- 概要だけ取得できた状態で公式過去問を取得済みと誤判定しない。

## 復習タイミング入力の能力表示・受付ゲート（2026-10-14）
- 復習間隔の自由入力を求める**前**に、利用中のAIアプリ・接続機能で実際に提供できる範囲を表示する。未検証の機能は「対応可能」と断定しない。
- 通常チャットの基本対応：復習間隔の解釈、学習記録への予定反映、チャット再開時の期限判定（必要な履歴・現在日時が確認できる場合）。チャットを閉じた状態での時刻指定の自動通知・自動出題は、実行経路が確認できない限り**非対応**。
- 入力例「3分後、1時間後」は**予定の記録**としてのみ受け付ける。ユーザーが自動通知・自動出題を要求した場合、実行可能なスケジューラと通知手段が検証されていなければ受付拒否。黙って予定記録だけに読み替えない。
- **画面 REVIEW_CUSTOM_INPUT**：注意書き「この画面で設定できるのは復習予定の記録です。指定時刻に自動通知・自動出題する機能は、現在のチャットで実行可能と確認できない限り利用できません。」を表示→自由入力。
- **画面 REVIEW_VALIDATE**：間隔の単位・正の数・重複・昇順・日時基準・実行能力を検証する。対応可能なら REVIEW_CONFIRM（解釈した予定と『自動通知なし』を表示）→明示承認→PLAN_REVISED→PLAN_PREVIEW。対応不能なら REVIEW_REJECT（受け付けられない要求と理由を表示）→「1 予定の記録として設定し直す／2 別の間隔を入力／3 復習メニューへ戻る」。承認・設定反映・成功報告は禁止。
- ユーザーが通知を希望する場合、実際に利用可能な別機能があると確認できた場合のみ、その別機能としての設定方法と制約を案内する。学習システム内で設定完了と偽らない。
- 回帰テスト：予定記録の短時間指定は受理、非対応の自動通知要求は拒否、入力前の注意表示、拒否後の再入力・戻る、無効な間隔拒否、承認前の反映禁止。
