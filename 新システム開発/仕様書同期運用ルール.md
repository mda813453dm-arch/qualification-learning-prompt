# 仕様書同期運用ルール
最終更新：2026-10-14

## 目的
資格学習システムの改修で実際の動作と公開仕様書がずれることを防ぐ。note等から参照される「資格学習システム_現行総合仕様書_20261014.md」を常に現行仕様の入口として維持する。

## 正本と更新単位
- 公開向け総合仕様：`新システム開発/資格学習システム_現行総合仕様書_20261014.md`
- AI実行仕様：`新システム開発/AIアプリ学習開始プロンプト_開発テスト版.md`
- 個別詳細仕様：`新システム開発/*仕様*.md`、診断・更新等の関連仕様
- 決定的ルール：`新システム開発/src/` の実装

ユーザー体験、状態遷移、保存データ、固定UI、採点、出題、復習、対応資格、対応AI、セキュリティ、外部連携、実装状態が変わる改修は「仕様影響あり」とする。

## 必須ルール
仕様影響ありの変更では、同じ変更単位で総合仕様書も更新する。実装だけ、実行プロンプトだけ、詳細仕様だけを変更して総合仕様書を放置しない。
総合仕様書は一般読者向け説明と詳細仕様の両方を更新する。新機能が未実装/未検証なら、その状態も明記する。実装完了・実機PASS後は「未実装」の記載を更新する。
単なるテスト追加、誤字、コメント、内部リファクタ等で利用者向け仕様が変わらない場合は総合仕様書更新を必須としない。

## 自動チェック
GitHub Actionsの仕様同期チェックで、仕様影響ファイルが変更されたコミット/PRについて総合仕様書も変更されているか確認する。総合仕様書が変更されていなければFAILとし、同期漏れを検出する。
このチェックは「内容が意味的に完全一致している」ことまで自動保証するものではない。レビュー/実機確認では総合仕様書の説明、詳細仕様、実装状態も確認する。

## note公開資料としてのルール
総合仕様書は単独リンクで初見読者が理解できる文章を維持する。専門用語だけで機能を説明せず、利用者目線の説明を先に置く。開発中機能を利用可能と誤認させない。
