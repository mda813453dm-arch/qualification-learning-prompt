## 1. 役割と権限

| AI | 主担当 | レビュー・支援 | 完了判定の権限 |
| --- | --- | --- | --- |
| **ChatGPT** | 開発統括、仕様調停、統合、CI/公開判断、Notion/GitHub同期 | 全領域の再検証 | 統合判断。実機未確認は明示 |
| **Claude** | 出題・採点・復習・引継ぎ・過去問取込／バックエンド | MuseのUI変更が学習記録を壊さないか確認 | 担当修正の提案・試験結果。最終公開はしない |
| **Muse** | Widget・モバイル画面・Playwright/CI・不具合再現性 | Claudeのエンジン変更がUIを壊さないか確認 | 担当修正の提案・試験結果。最終公開はしない |
| **Perplexity** | e-Gov・試験実施機関・公式PDF/正答・一次技術資料の独立照合 | 法令・原典・問題番号の整合性検査 | 根拠の確認／未確認の区別。コードの正答確定はしない |

これは担当の初期設定であり、AIの実能力・利用可能な接続権限を保証しない。各Issueで実際の実行者・レビュー者を確定し、必要に応じて役割を調整する。Claudeの実行はNotion共通ルールの承認条件に従う。ユーザーの指示が優先する。

## 2. 絶対に守る仕様
1. 出題・正答確定・採点・次問・進捗更新は**プログラムだけ**。AIはヒント・解説・検証補助のみ。
2. `questionId`・年度・問番号・選択肢・公式正答・出典の同一性を緩和しない。原資料を推測で補わない。
3. 回答前の正答漏洩禁止。AI詳説は利用者の明示操作でのみ。回答後の短い訂正・次問はAIの生成完了待ちに依存させない。
4. iPhone/Androidで操作可能な画面と、既存学習セッションの旧Widget URI互換を保持。現行画面変更時は `widget-current.js` と `mcp.js` の旧版対応を確認。
5. 追加課金・有料APIを前提としない。パスワード・APIキー・個人の学習履歴はGitHub Issue・PR・Notionに貼らない。

## 3. GitHub運用
- **1 Issue＝1主責任者、原則1領域**。Issue本文に実行者AI・レビューAI・対象ファイル・期待動作・再現方法・確定事実/推測・受入条件を記入する。
- 同じファイルの並行編集は避ける。各担当は必ず**作業開始前のHEAD**を確認し、別担当の変更を無断で上書きしない。競合時はChatGPTが順序を決定。
- コード変更前に「正常系・旧不具合・失敗経路」を明記。安全な最小差分と、新旧回帰テストの追加を基本とする。
- PR（利用可能な場合）かコミットURLで差分を提出。主担当以外が仕様外変更を確認し、問題があれば戻す。PRの自動作成・AI同士の直接通知は利用できる権限次第。
- 直接 `deploy-request.txt` を更新して公開を起動するのは、**ChatGPTによる統合判断と必要な承認の後**だけ。他AIは勝手に公開しない。
- GitHub issueやNotionページを作ったことを「他AIへ通知済み」とは扱わない。実際にメッセージを渡した/受領の確認ができた場合だけ「通知済み」と記す。

## 4. 受入・公開の判定
`未着手 → 調査中 → 原因確定（または候補明示） → 修正案 → 実装 → CI検証 → Cloud Run配置 → 公開版検証 → iPhone/Android実機確認 → 完了`
- CIで最低限、変更に対応するエンジン `npm test`、PDFパーサー、Widget Playwrightの対象回帰（Chromium/WebKit、375px、focus、次問、採点/正答の同一性、旧URI）を確認。実行されなかったテストを合格としない。
- 現行 `deploy-google-cloud.yml` には `widget-preflight` の再利用ワークフローゲートがある。実際にCIが通るかは別に確認する。
- GitHub Actions成功 ≠ Cloud Run配置 ≠ 公開後スモーク成功 ≠ ChatGPTアプリ内の実機成功。区別してIssue/Notionに記録する。
- 修正対象外の回帰に失敗した場合も新規問題として記録し、安易にテストを無効化しない。

## 6. AI別の最初の作業
- **ChatGPT**：GitHub/Notionの共有入口を維持、Issueを採番、作業の担当と競合を管理、CI/公開を判定。
- **Claude**：エンジン/学習状態・PDF取り込みの変更が採点と履歴を壊さないか検証し、コード根拠付きで報告。
- **Muse**：Widgetの375px採点、先頭表示、WebKit/Android不具合、Playwrightの診断改善を担当。Notionの最新Muse→ChatGPT修正依頼を二重着手せず確認。
- **Perplexity**：公式問題・正答・条文等の参照元と照合手順を監査し、出典未確認の解説が正答と混同されないか調査。

このファイルは運用のルーター。法令や仕様の正本そのものではない。優先順位はユーザーの最新指示、システム上の承認・安全要件、Notion現行共通ルール、個別プロジェクト仕様、Issueの合意の順で確認する。
